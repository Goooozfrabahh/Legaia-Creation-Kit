# B2B manual DuckStation scenario — user operated only

Use the experimental IMG identified by the final B2B delivery manifest. Latest Build remains 4476a72. This is an animated-field-actor candidate, not behavior-preserving dialogue/story transplantation or a gameplay-certified build.

1. Keep the retail IMG, existing saves, previous exports and successful builds unchanged. Use your established separate test-copy/save workflow. Do not replace the retail disc or install over Latest Build.
2. Personally open `LCK_EXPERIMENTAL_B2B_NATIVE_ANIMATION.img` in DuckStation. Cold boot it, then use a compatible memory-card save and enter the selected original Rim Elm scene (`town01`). A savestate can restore old scene RAM/VRAM instead of loading these new resources; use a full reload of the candidate's scene for the native test. Other Rim Elm story variants were not patched.
3. Locate the three new References around native roots `(4800, 0, 2368)`, `(4928, 0, 2368)` and `(5056, 0, 2496)` (X, editor-up Y, Z): X/Z tiles `(37,18)`, `(38,18)`, `(39,19)`. Exact final root/model/clip/context IDs are in `B2B_NATIVE_ANIMATION.json`; the `.lckproject` stores the separate visual-center transforms and FormKeys.
4. The first and third use the same Balden P1[1] Base resources; the middle uses Bubu1 P1[1]. Watch each for at least 20 seconds. Record whether geometry assembles into the intended donor model, whether the pose changes/loops, texture/palette correctness, flicker, disappearing groups and load stability. The duplicate starts with the same clip/phase/rate, so synchronized-looking loops alone are not evidence of shared mutable state.
5. Check Vahn's face and normal resident character appearances, including ordinary dialogue/facing changes with original NPCs. Check original Rim Elm actors, exits, stairs and normal movement separately. New donor dialogue, ambient walking, triggers and story behavior are not expected to have been transplanted. Collision equivalence for new actors is not certified.
6. The candidate project can be reviewed when you choose to use a B2B editor build; no new editor is installed by this task. Open that saved project against its recorded master, duplicate/move one new Reference by a compatible native root increment (64 or 128 units), change a compatible clip if desired, reset preview frame to 0, save/reopen, and export to a NEW IMG. Delete a copy and repeat. Rebuild from the recorded master instead of treating an exported IMG as ownership evidence. Compare the remaining Reference IDs/state and per-object reports. Do not use a legacy build's lack of new controls as evidence about this checkpoint.
7. For every native trial, report the candidate hash, save/story state, which Reference/model/clip was visible, screenshots and pass/fail separately for load, animation, textures, original actors and collision. If it fails to load, retain the failed output/debug reports and supply the observed symptom; do not overwrite it with another trial.

Automated packaging/readback and original-instruction simulation already have separate logs. Only your results can establish manual native gameplay evidence.
