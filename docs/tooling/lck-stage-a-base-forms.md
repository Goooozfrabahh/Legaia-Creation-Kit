## A1 — identity and database

Logical FileId plus 24-bit per-file local_id is the permanent FormKey. The displayed 32-bit FormID adds an 8-bit load-order position at query time. The import registry allocates master identities and is serialized independently of source fingerprints. Equal resources do not merge definitions. Base and Reference maps cannot share keys. Native provenance, shared definition properties, reference-specific state and collision ownership handles are separate.

Database transactions clone, validate and commit the full effective state and reverse indexes. Command history restores complete records and retains allocation high-water marks so abandoned identities are never reused. Retail reference edits/deletions are active-layer overrides; the master layer is untouched. Disabled and deleted are separate states. Use Info counts known dependencies and reports incomplete coverage explicitly.

No UI/native compiler changes in this checkpoint. Stage A is not yet complete.

## A2 — project persistence and migration

`lck_project.rs` stores LCK_PROJECT_V1 with schema version, logical project/master IDs, disc fingerprint, complete master/import registry and allocator state, active records/overrides/tombstones, cell-copy identities, legacy UID bindings, native adapter provenance, collision associations and exact preserved sidecar bytes. Save validates and reparses before calling the existing optimistic, durable atomic writer. The extension guard prohibits saving over a retail IMG. Missing/stale master or donor evidence yields diagnostics without deleting records.

`form_legacy.rs` adapts original source records and existing `.lckscene` state into shared definitions and individual references. The source registry uses original scene/record/cell identities; hashes only validate evidence. Legacy source text is retained exactly. The adapter preserves names, native/foreign identities, static-copy flags, per-axis transforms, NPC choices, authored/generated collision payloads and cell-copy IDs. Reimport retains existing mappings and marks missing created draws as project tombstones.

## A4 â€” native compatibility adapter

`ps1_export::prepare_project` freezes and validates active records, resolves the selected Cell through `form_bridge`, and feeds that projection into the existing unrestricted/strict writers. It does not replace the PS1 compiler or allocate FormKeys from native offsets. Existing native Ctrl+D copies retain INSTANCE routing; newly placed static architecture uses explicit FOREIGN_STATIC input even when the source and destination cell match. Every record is saved independently of serializer coverage. Shared-material edits and unresolved geometry/ownership adapters append FAILED PROJECT NATIVE ADAPTER diagnostics; GUI completion now treats general failed operations as incomplete, including when no foreign-import counter failed.

The export report includes permanent Reference/Base/Cell identities, deleted/disabled state, legacy writer witness and distinct encoding/readback/loader/render/collision status. Native readback and existing native registration reports do not establish gameplay behavior. A missing preview adapter does not remove a record from the project.

Exact saved collision journal bytes can supply the existing hash-bound ownership adapter in memory when the adjacent sidecar is absent. Image, MAP, descriptor and native model witnesses still validate. A physical sidecar takes precedence, including validation errors; no project fallback overwrites or silently replaces it. The existing journal reconciliation and source-resource retirement mechanisms remain authoritative. Project switches clear transient render caches. Switching source discs keeps the previous project recoverable and prevents projecting its records through the wrong disc index.

Native limits remain explicit: shared preview tint has no verified native material override writer; arbitrary new behavior/collision/resource relationships require an established native adapter. Actor, terrain and other record families remain valid database records even when a preview/import serializer is unavailable. Missing dependencies stay recorded. This architecture neither fixes nor certifies the separately tracked Rim Elm runtime freeze, live heap budgets, script behavior or gameplay. Unrestricted attempts remain enabled and partial outputs remain conspicuously incomplete.
